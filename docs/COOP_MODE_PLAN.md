# 協力プレイモード改善計画

- 更新日: 2026-09-16
- 対象: v1.1以降
- 状態: 要件案・段階実装計画を整理済み（未実装）

## 1. 目的

チーム登山を、同じチームの全員が声を掛け合い、最後の1人までゴールさせるモードへ改善する。

ギミックを増やしすぎず、次の2種類に限定する。

1. チーム集合ポイント
2. 踏み台ジャンプと救助リフト

既存の大人数プレイ、個人操作、観戦機能を活かしながら、速いプレイヤーが仲間を待つ・助ける理由を作る。

## 2. 現行仕様

現在のチーム登山には次の機能がある。

- 1～4のチーム選択
- チームカラーの統一
- 味方の頭上への着地
- 味方を踏み台にした場合のジャンプ補正
- 協力エリアと高壁を含むチーム専用ステージ

現時点では、踏み台役が上部へ合流するための救助手段と、チーム全員のゴールを評価する専用順位ルールはない。

## 3. 目標ルール

### 3.1 チームクリア

- チームの人間プレイヤー全員がゴールすると、そのチームをクリアとする。
- チーム記録は、最後のメンバーがゴールした時刻とする。
- 先にゴールしたメンバーは観戦モードへ移り、残った仲間を応援できる。
- タイムアウト時は、ゴール人数が多いチームを上位とする。
- ゴール人数が同じ場合は、未ゴールメンバーの最低高度が高いチームを上位とする。
- さらに同点の場合は、ゴール済みメンバーのゴール時間合計で判定する。

CPU、切断、リタイアをチームクリア人数へ含めるかは、実装フェーズ1で現行の部屋補充ルールと合わせて確定する。

### 3.2 設計原則

- 協力成功後に解放した通路は再ロックしない。
- 1人が同じ場所に残り続ける役割を作らない。
- 失敗しても何度でも再挑戦できる。
- 踏み台役を取り残さない救助手段を必ず用意する。
- 一部メンバーが先行しても、最後は全員がゴールできる。
- チームごとの進行状態を分離し、他チームの解除へ便乗できないようにする。
- バトルロワイヤル登山の物理、順位、ステージへ影響させない。

## 4. 採用ギミック

### 4.1 チーム集合ポイント

- 各メンバーが集合床へ一度触れると、その人の到着を記録する。
- 全員が同時に床へ乗る必要はない。
- `赤チーム 3 / 5人到着`のように進捗を表示する。
- チーム全員が到着すると、次の区間をそのチームに対して永久解放する。
- 到着状況はプレイヤー画面と観戦画面の両方に表示する。

### 4.2 踏み台ジャンプと救助リフト

1. 1人が踏み台になり、別のメンバーが終盤の高壁を越える。
2. 上部へ到着したメンバーが救助スイッチを押す。
3. 同じチーム向けの救助リフトを永久起動する。
4. 踏み台役を含む下側のメンバーが上部へ合流する。
5. チーム全員がゴールへ進む。

踏み台ジャンプは終盤の1か所に限定し、踏み台だけでゴールへ到達する構造にはしない。

## 5. 段階実装計画

各フェーズを実装、ローカル確認、調整、コミット、プッシュまで完了してから次へ進む。

### フェーズ1: チーム勝敗ルール

実装範囲:

- チーム全員のゴールによるチームクリア判定
- 最終メンバーのゴール時刻によるチーム順位
- タイムアウト時の順位判定
- HUDのチームゴール進捗
- チーム単位のリザルトとCSV

確認項目:

- 1人がゴールしても試合が終了しない。
- チーム全員の状態が順位へ反映される。
- タイムアウト時の比較が仕様どおりになる。
- バトルロワイヤル登山へ影響しない。

### フェーズ2: 集合ポイントの表示と記録

実装範囲:

- チーム・スカイベース中盤への集合エリア配置
- メンバーごとの到着記録
- チームカラーのランプと人数表示
- 観戦画面とステージプレビューへの表示

この時点では進行を止めず、表示と状態記録だけを検証する。

確認項目:

- 一度触れたメンバーの到着状態が保持される。
- チームごとの状態が混ざらない。
- CPU、切断、再接続時の状態が破綻しない。
- PC、スマートフォン、観戦画面で表示が収まる。

### フェーズ3: 集合ゲートの有効化

実装範囲:

- 未集合チームの次区間への進行制限
- 全員到着時の永久解放
- チーム別の衝突・通過判定
- 解放演出と通知

確認項目:

- 未解放のチームだけが制限される。
- 別チームの解除へ便乗できない。
- 解放後に再ロックされない。
- 切断や人数変更で進行不能にならない。

### フェーズ4: 最終高壁の配置

実装範囲:

- 終盤の踏み台ジャンプ用高壁
- 上部の救助スイッチ表示
- 動作確認用の常時稼働リフト
- カメラ、着地点、当たり判定の調整

確認項目:

- 味方を踏み台にして安定して高壁を越えられる。
- 踏み台役が押し出しで落下し続けない。
- 頭上の足場に衝突して進行不能にならない。
- スマートフォン操作でも成功できる。

### フェーズ5: 救助スイッチとリフト

実装範囲:

- 救助スイッチの接触判定
- 同じチーム向けリフトの永久起動
- 起動者、対象チーム、状態の同期
- 起動演出と観戦通知

確認項目:

- 踏み台役を含む全メンバーが救出される。
- 他チームのリフト状態と混ざらない。
- 起動後は何度でも利用できる。
- リフト上のキャラクターが床と一緒に移動する。

### フェーズ6: コースと演出の仕上げ

実装範囲:

- 集合ポイントまでの難易度調整
- 高壁周辺の混雑対策
- チーム進捗HUD
- 協力成功エフェクト
- 観戦者向けイベント表示
- CPUの集合・救助行動
- 自動テストとステージ到達性検証
- 関連ドキュメント更新

## 6. 検証方法

- 2つ以上のブラウザで同じ部屋へ参加する。
- 最小人数と最大人数の両方を確認する。
- 各チームの集合状態を意図的にずらして確認する。
- 踏み台役、先行役、後続役を交代して確認する。
- 途中切断、再接続、リタイア、タイムアウトを確認する。
- 観戦者から両チームの進捗が理解できるか確認する。
- `check:stages`、型検査、Lint、ビルド、サーバーテストを各フェーズで実行する。

## 7. 実装前に確定する事項

- 1チームの最小・最大人数
- CPUをチームクリア条件へ含めるか
- 切断者の猶予時間と失格条件
- リタイアしたメンバーがいるチームの扱い
- 全チームの完走を待つか、完走済みチーム確定後の制限時間を設けるか
- CSVに出力するチーム名と補助記録

これらはフェーズ1開始時に決定し、確定内容をゲーム仕様書とシステム設計書へ反映する。
